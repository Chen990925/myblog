# Redis 2：缓存一致性（结合项目）

## 一、本质

缓存是 DB 的冗余副本，更新传播有时差。主线：① DB 更新了缓存怎么跟着更新（写策略）② 并发读写怎么保证最终一致（读策略+时序）③ 项目怎么做的。

## 二、四种写策略

| 策略 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| Cache Aside（旁路缓存） | 读 miss 查 DB 回填；写**先 DB 后删缓存** | 简单，主流 | 删失败有脏窗口 |
| Read/Write Through | 缓存代理读写并同步 DB | 上层无感 | 依赖中间件 |
| Write Behind（异步写回） | 先写缓存异步批量写 DB | 写性能高 | 宕机丢数据 |

**结论：主流用 Cache Aside**，项目系统参数刷新是其变体。

## 三、先 DB 后删缓存 vs 先删缓存后 DB（高频追问）

- 先删后 DB：删缓存后、更新 DB 前有请求读 → miss → 查 DB 旧值 → 回填旧值 → DB 更新完缓存是旧值（脏窗口大，可能长期不更新）
- 先 DB 后删：只有删缓存前的短暂旧值窗口（小）

**删缓存失败兜底**：
1. 重试队列（MQ 异步重删）
2. **延迟双删**：更新 DB 后删缓存 → 等 500ms~1s（大于读回填耗时）→ 再删一次，消除"删缓存与读回填旧值"竞态
3. **Canal**：订阅 MySQL binlog → 异步删缓存（无侵入，最终一致）

**读写并发四种脏场景**：① 读回填 vs 删缓存竞态 → 延迟双删；② 删缓存失败 → 重试/Canal；③ DB 更新失败 → 不删（一致）；④ 双线程更新 → 只要删成功，下次读回填最新 → 最终一致。

## 四、项目真实实现：SysparmRedisManager delete + 全量重建

```java
public void refreshCache4SysParam() {
    List<...> params = dao.selectAll();        // 1. 全量查 DB
    redisTemplate.delete(SYSTEM_PARAM_KEY);    // 2. 删旧缓存
    redisTemplate.boundHashOps(SYSTEM_PARAM_KEY).putAll(params);  // 3. 全量重建
}
```

**分析与优化建议（面试讲）**：
- 删建窗口：删了旧缓存、没写完新缓存 → 读 miss 打 DB（类似击穿窗口）
- 改进：① 先写临时 key 再 `rename` **原子切换**；② 双 key 交替（keyA/keyB 轮流写）；③ 刷新加分布式锁；④ 接受短暂不一致（系统参数变更低频）
- 大 Hash 的 `del` 是 O(N) 阻塞命令 → 用 `unlink`（4.0+ 异步删）或 hscan+hdelt 分批

## 五、项目一致性等级映射

| 场景 | 策略 | 一致性 |
|---|---|---|
| 系统参数（SysparmRedisManager） | 先删后建全量重建 | 最终一致（有窗口） |
| common-cache 静态缓存（H2 本地） | 定时刷新 + data-sync 5 分钟对账 | 最终一致（分钟级） |
| 行情缓存 | 订阅/轮询更新 | 最终一致（秒级） |
| 成交/报价状态 | 分布式锁防并发 + 状态机 | 强一致（靠锁） |

**可讲点**："一致性要求按业务对齐：系统参数分钟级可接受，成交状态必须强一致（Redis 锁+状态机），行情秒级。不是所有缓存都要强一致。"

## 六、面试话术（1 分钟版）

> "缓存一致性用 Cache Aside：读 miss 查 DB 回填，写先更新 DB 再删缓存。为什么先 DB 后删？先删会有'删了还没更新 DB'窗口，读请求回填旧值脏窗口大。删失败兜底：重试队列、延迟双删、Canal binlog。系统参数缓存是 delete+全量重建，属于最终一致——我 review 时优化过两点：删建窗口改 rename 原子切换、大 Hash 的 del 改 unlink 异步删。要强一致就别用缓存，缓存给的是最终一致+高性能。"

## 七、高频追问

- 延迟双删延迟怎么定？→ 大于读回填最大耗时（压测，一般 500ms~1s）
- 为什么删缓存不更新缓存？→ 更新有并发写覆盖问题；删了让下次读自然回填，逻辑简单
- Canal 了解吗？→ 订阅 binlog（主从同步机制）异步删缓存/同步异构数据，无侵入
- 缓存和 DB 强一致可能吗？→ 不可能（CAP），只能最终一致；强一致直接读 DB
- 项目刷新窗口怎么消除？→ rename 原子切换 / 双 key 交替 / 接受短暂不一致
