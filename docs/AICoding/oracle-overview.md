# 数据库（Oracle）主题总览（对话总结）

> 本文档总结"简历面试准备——数据库（Oracle）"对话的全部产出，作为入口和索引。
> 与 JVM / 并发编程 / Redis 主题同属面试准备系列，假设环境 **8 核 8 线程 / 500GB 硬盘 / 32GB 内存**。

## 一、对话目标与约定

- 目标：基于本项目（cloudsrv，银行间/交易所指令交易 OMS 系统，Oracle 数据库）准备简历与面试内容
- 用户需求：Oracle 了解不深，从面试重点切入（慢 SQL、索引优化、实战排查）
- 当前阶段：数据库板块已完整（Oracle 基础与项目 SQL / 慢 SQL 定位 / 索引优化 / Oracle 特有优化点 / 实战排查 + 速记卡）

## 二、本主题已覆盖内容（按对话顺序）

1. **项目 Oracle 现状**：thin 连接 + Druid PSCache、MERGE INTO 汇总、ROWNUM 嵌套分页、序列 ID（→ `数据库0-准备点清单.md` §0）
2. **Oracle 基础与项目 SQL 特性**：vs MySQL 三个不同、ROWNUM 两坑、MERGE 原子 upsert、序列批量取号、PSCache 软解析（→ `数据库1-Oracle基础与项目SQL特性.md`）
3. **慢 SQL 定位**：Druid/v$sqlarea/AWR 三通道发现、执行计划抓取与读法、七类根因、统计信息过期（→ `数据库2-慢SQL定位.md`）
4. **索引优化**：B+ 树原理、访问方式、七种失效清单、组合索引三原则、覆盖索引、维护成本（→ `数据库3-索引优化.md`）
5. **Oracle 特有优化点**：HWM 高水位（缩表本质）、分区表、统计信息、绑定变量（→ `数据库4-Oracle特有优化点.md`）
6. **实战：慢 SQL + 缩表排查**：四步排查流程、STAR 话术、追问准备、变体案例（→ `数据库5-实战慢SQL与缩表排查.md`）

- **主打案例**：线上突然超级慢 SQL + 缩表（HWM）排查——统计信息过期 + 高水位线不降双根因，最能体现 Oracle 实战深度

## 五、简历落点（可直接引用）

> 负责 Oracle 交易系统 SQL 性能优化：通过 Druid 慢 SQL 监控与 AWR 分析定位 TOP SQL，基于执行计划识别全表扫描、索引失效与统计信息过期问题，设计"客户+日期+证券"组合索引与覆盖索引；主导线上慢 SQL 与表缩容排查，定位统计信息过期与高水位线未下降双根因，通过收集统计信息与 SHRINK SPACE 在线收缩将查询从十几秒降至毫秒级，并沉淀"清理→收缩→收集统计信息"清理作业规范。
