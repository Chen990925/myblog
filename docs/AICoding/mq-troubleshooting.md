# MQ 5：生产问题排查

## 一、排查总纲：消息四个"不"

```
先定性：是"丢、重、乱、积"哪一种？（现象 → 链路定位）
丢消息 → 生产/Broker/消费 三段日志排查
重复消费 → 幂等兜底 + 找重复来源（重试重发/ACK 丢失）
乱序 → 队列路由/并发消费排查
堆积 → 消费吞吐 < 生产速率（慢消费/线程不够/外部依赖）
```

## 二、场景 1：消息堆积（最常出，呼应 JVM 案例 6）

**现象**：消费 lag 持续上涨，回报/清算延迟；控制台显示堆积几万~几十万。

**排查**：
```
① 消费进度：mqadmin consumerProgress -g 消费组 → lag 趋势
② 消费线程：jstack 消费线程状态（BLOCKED=DB 锁/WAITING=外部依赖）——呼应并发排查
③ 消费逻辑耗时：慢 SQL？外部调用慢？死循环？
④ 线程数/批量：consumeThreadMax 不够？单条处理太慢？
```

**根因分类**：
| 根因 | 解法 |
|---|---|
| 消费端慢 SQL（无索引/锁冲突） | 优化 SQL + 加索引（呼应数据库块） |
| 外部依赖慢（Feign/DB） | 超时 + 异步化 + 隔离 |
| 消费线程数不足 | 调 consumeThreadMax |
| 单条坏消息阻塞 | 重试上限 + DLQ（隔离坏消息） |
| 生产速率暴涨 | 削峰 + 扩容消费者 |

项目落点："回报堆积排查：consumerProgress 看 lag → jstack 消费线程，栈底慢 SQL 是数据库问题、栈底 Feign 是外部依赖；处理过消费端慢 SQL 导致回报堆积。"

## 三、场景 2：重复消费

**来源**：① 消费重试重投 ② 生产端重试重发 ③ ACK 丢失（消费成功但 ACK 没到，重投）

**排查**：业务日志同一订单出现两次处理记录（间隔符合重试节奏）→ 确认来源段。

**解决**：幂等兜底（唯一约束/Redis 去重/状态机）——**不是排查掉重复，而是让重复无害**。

## 四、场景 3：消息丢失

**四段对证据**：
```
① 生产端是否发出？    生产日志（asyncSend onSuccess/onException）+ 本地消息表
② Broker 是否收到？   mqadmin queryMsgById（按 msgId 查）
③ Broker 是否落盘？   刷盘策略（同步/异步）+ 是否有宕机记录
④ 消费端是否消费？    消费日志 + offset 是否推进 + ACK
```
- 结论：哪段没证据就是哪段丢；前提是每段有日志和监控

话术："丢消息排查按四段对证据：生产日志（发出没）、queryMsgById（Broker 收到没）、刷盘配置（落盘没）、消费日志+offset（消费没）。哪段没记录就是哪段丢。"

## 五、场景 4：顺序错乱

**现象**：同一订单"撤单"先于"下单"，状态回退。
**排查**：消息是否同队列（key 路由）？并发消费？消费端有状态机？
**解决**：① 按 orderId 选队列 ② 顺序消费 ③ 状态机校验（前置状态不对拒绝/等待）

## 六、场景 5：消息延迟

**排查**：消费线程阻塞（jstack）？Broker 磁盘慢（同步刷盘 IO 瓶颈）？lag？
**解决**：消费端优化 + 刷盘策略权衡 + lag 告警

## 七、工具（加分）

```
mqadmin：consumerProgress（消费进度）/ topicList / queryMsgById / queryMsgByKey / clusterList
控制台：rocketmq-console（lag/topic/消息查询）
监控：消费 lag 告警（堆积超阈值报警——建立基线）
```

项目落点："生产排查用 mqadmin + 控制台：consumerProgress 看 lag、queryMsgByKey 按订单号查链路；关键链路配 lag 告警。"

## 八、面试话术（1 分钟版）

> "MQ 生产问题按'丢、重、乱、积'四类定性再排查：堆积先 consumerProgress 看 lag 再 jstack 消费线程定位（慢 SQL/外部依赖/线程不足）；重复消费靠幂等兜底让重复无害；丢失按四段对证据（生产日志→queryMsgById→刷盘配置→消费 offset）；乱序靠按 key 路由队列+顺序消费+状态机。排查前提是每段有日志和 lag 告警。"

## 九、高频追问

- lag 多少算堆积？→ 看业务容忍度（回报秒级延迟），lag 持续上涨不回落就处理；建基线告警
- 批量消费的坑？→ 吞吐高但批量内一条失败整批重投（放大重复）→ 幂等更重要
- DLQ 怎么处理？→ 查日志找根因→修复→手动重投/补数据→更新监控
- 怎么确认重复是生产还是消费引起？→ msgId 相同=消费重投（ACK 丢失/重试）；msgId 不同=生产重发
- 回报堆积为什么影响下单？→ 消费线程占满/积压 → 下游状态不更新 → 上游查询超时（雪崩，呼应并发案例）
