# 微服务 6：生产问题排查（微服务场景）

## 一、服务摘除 / 注册问题

```
现象：实例被摘除后仍被调用 / 调用不到新实例
排查：
① Nacos 控制台看实例列表与健康状态
② 服务端心跳是否正常上报（网络抖动、GC 停顿导致心跳超时——呼应 JVM）
③ 消费者本地服务列表缓存是否过期
```

## 二、超时与雪崩（项目真实场景）

```
现象：外部依赖变慢 → 调用方线程池耗尽 → 全链路变慢（CFETS 变慢案例）
排查：
① jstack 看线程栈底（Feign/HttpClient 阻塞）——呼应并发排查
② 查 Feign 超时配置（项目 readTimeout=600s，过长）
③ 看下游 RT 监控（P99 突增）
解决：收紧超时（分级 3s/10s）+ 熔断 + 隔离 + 异步化（回报链路已 MQ 化）
```

## 三、配置变更引发的故障

```
现象：改 Nacos 配置后服务异常（路由刷新异常、Bean 重建、Metaspace 增长）
排查：配置变更时间点 vs 故障时间点；jstat/jcmd 看类加载与 Metaspace
解决：配置灰度发布、控制刷新频率、@RefreshScope 慎用（只对 Bean 生效）
```

## 四、排查工具链（微服务视角）

| 工具 | 用途 | 项目现状 |
|---|---|---|
| Nacos 控制台 | 服务列表/实例健康/配置历史 | ✅ 可用 |
| Feign 日志 | 跨服务调用打点（BASIC：方法/URL/状态码/耗时） | ✅ 已开 |
| 链路追踪（SkyWalking/Zipkin） | 跨服务耗时定位 | ❌ **短板，建议引入** |
| 日志聚合（ELK） | 多服务日志统一检索 | ❌ 短板 |
| Sentinel 控制台 | 流控/熔断实时监控 | ❌ 未引入 |

## 五、面试话术（1 分钟版）

> "微服务排查三看：一看注册中心实例健康（Nacos 控制台，心跳异常常是 GC 停顿或网络问题），二看跨服务调用链（我们靠 Feign 日志打点，没有链路追踪是个短板，建议引入 SkyWalking），三看超时与线程（jstack 栈底 + Feign 超时配置）——我们遇到过外部依赖变慢导致线程池耗尽，根因就是 readTimeout 太长 + 无熔断。配置变更类故障先对时间点，再控制刷新频率。"

## 六、高频追问

- 怎么定位跨服务耗时？→ 链路追踪（TraceId 透传）+ Feign 日志打点；没链路追踪时靠日志时间戳人工串联
- 服务调用不到的排查顺序？→ 注册中心（实例在不在/健康）→ 网络（能通吗）→ 应用（线程池/连接池满没）→ 下游（响应正常吗）
- GC 停顿会影响服务发现吗？→ 会：心跳上报超时（15s）被标记不健康，长时间 STOP-THE-WORLD 会触发剔除（呼应 JVM 调优）
- 配置改了但没生效？→ 检查 @RefreshScope、配置优先级（Nacos > 本地）、客户端长轮询是否正常
- 怎么提前发现雪崩风险？→ 监控线程池活跃数/队列水位 + 下游 RT P99 + Feign 异常率告警（呼应并发板块线程池监控）
