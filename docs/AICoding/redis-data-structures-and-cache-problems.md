# Redis 1：数据结构 + 缓存三大问题（结合项目）

## 一、五种基本数据结构

| 结构 | 适用 | 底层 | 项目用法 |
|---|---|---|---|
| String | 缓存对象/计数/锁/会话 | SDS（预分配+惰性释放，O(1) 取长度） | 锁（setIfAbsent）、幂等标记、增量时间戳（XOMS_MD_INCREMENT_*） |
| Hash | 对象字段级读写 | 小=ziplist，大=hashtable | 系统参数缓存（boundHashOps putAll，hGet 按参数名取） |
| List | 队列/时间线 | quicklist | RedisUtil 提供 lSet/lGet（业务少用） |
| Set | 去重/交集并集 | intset/hashtable | - |
| ZSet | 排行榜/延迟队列 | skiplist+hashtable | 延迟队列可做（score=时间戳） |

- Hash vs String 存对象：Hash 可只改一个字段（更新价格），String 整个序列化/反序列化；字段少用 String 省内存
- 为什么 String 能存数字：value 按字节存，incr 原子（单线程命令）

## 二、单线程模型（贯穿所有问题的底层认知）

- 快的原因：纯内存 + 单线程执行命令（IO 多路复用 epoll）+ 无上下文切换/锁竞争
- 命令天然原子（incr/setnx 不用加锁）
- 代价：**慢命令阻塞所有请求**——`keys *`（O(N)）禁，大 key `hgetall`/`del` 慎
- 6.0+ 多线程只用于网络 IO，命令执行仍单线程
- 项目落点：系统参数大 Hash 的 hgetall 全量取 = 慢命令隐患

## 三、缓存三大问题

### 1. 穿透（Cache Penetration）
- 现象：查不存在的数据 → 缓存没有 → 每次打 DB
- 方案：缓存空值（TTL 短 5 分钟内）/ 布隆过滤器（可能误判存在，不遗漏）/ 参数校验
- 项目：系统参数全量预热，天然无穿透；按主键查的缓存需兜底

### 2. 击穿（Cache Breakdown）
- 现象：单热点 key 过期瞬间大量请求打 DB
- 方案：互斥锁重建（setnx，一个请求重建其他等待/返回旧值）/ 逻辑过期（value 带过期时间+异步刷新）/ **不过期+定时刷新（项目 Sysparm 模式）**
- 项目落点：Sysparm delete+重建的**删建窗口** = 击穿窗口 → 优化见一致性块

### 3. 雪崩（Cache Avalanche）
- 现象：大量 key 同时过期 / Redis 挂 → 海量打 DB
- 方案：TTL 随机抖动 / 多级缓存（本地 Caffeine + Redis）/ Redis 高可用（主从+哨兵）/ DB 限流降级（Sentinel）

### 对比表（背熟）

| 问题 | 本质 | 核心方案 |
|---|---|---|
| 穿透 | 查不存在数据 | 缓存空值 / 布隆过滤器 / 参数校验 |
| 击穿 | 单热点 key 过期瞬间 | 互斥锁重建 / 逻辑过期 / 不过期+定时刷新 |
| 雪崩 | 大量 key 同时过期 / Redis 挂 | TTL 随机抖动 / 多级缓存 / 高可用 / 限流降级 |

## 四、项目场景映射

| 场景 | 对应问题 | 可讲点 |
|---|---|---|
| 系统参数 Hash 缓存 | 击穿风险 | 全量预热 + delete+重建；重建窗口的击穿风险与优化 |
| 行情/基础数据（common-cache H2 本地） | 抗雪崩 | 本地缓存天然抗 Redis 挂 |
| 成交/报价 Redis 锁 | 锁场景（非缓存） | 见分布式锁块 |

## 五、面试话术（1 分钟版）

> "Redis 五种结构 String/Hash/List/Set/ZSet，项目里 String 做分布式锁和幂等、Hash 存系统参数。底层单线程执行命令，命令原子但慢命令会阻塞。三大问题：穿透查不存在数据用缓存空值+布隆过滤器；击穿是单热点 key 过期瞬间用互斥锁/逻辑过期/不过期+定时刷新（系统参数就是不过期+定时刷新）；雪崩是大量 key 同时过期用 TTL 抖动+多级缓存+高可用。排查时先区分是穿透、击穿还是雪崩，对症下药。"

## 六、高频追问

- 布隆过滤器误判？→ 只可能把不存在误判为存在（false positive），不会漏真实存在；可加缓存空值兜底
- 为什么 incr 原子？→ 单线程执行命令
- keys * 为什么禁用？→ O(N) 阻塞；用 scan 分批
- 缓存空值 TTL？→ 短（5 分钟内），太长占内存
- 热 key 除了过期还有什么问题？→ 单节点压力（见性能块）
- 项目击穿窗口怎么消除？→ rename 原子切换 / 双 key 交替
